What this model shows—and what it leaves out

This is a one-thread-per-output indexing example. Optimized matrix kernels can distribute work differently and use tensor cores. The four-SM cutaway is an illustration, not a specific GPU. Tiles drawn on its die are SMs, not individual CUDA cores.

Each block is assigned wholly to one SM. One SM can host several blocks when resources permit. The placement steps show one possible assignment; they do not predict order, duration, concurrency, occupancy, or throughput. Earlier placements remain drawn for tracking, without a claim that they are simultaneous.

A warp groups 32 threads within one block; a lane is a thread’s position 0–31 in that warp. Thread and warp labels describe work. A thread is not a dedicated physical core. A guard checks that an output exists before a thread reads inputs or writes a result.

Reference: NVIDIA CUDA Programming Guide. Numerical row/column inputs here are invented teaching values. No GPU executes this page.
