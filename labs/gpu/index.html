Module 3

GPU Architecture and Performance Engineering

Learn to predict a bottleneck from operations, shapes and data movement—then identify the evidence needed to test it.

From equations to hardware

You already know what attention computes. Now ask: which work runs together, which bytes move, and which resource prevents it running faster? Start from one projection, trace it onto a GPU, then test a performance hypothesis.

Ready to start? Begin with 3.1 after checking the prerequisites below. You need matrix shapes, a dot product, prefill/decode and KV-cache basics. Mathematical fluency can develop alongside the course: sums · shapes. These lessons do not certify implementation mastery.

Each lesson has a few concepts, a manipulable example, optional derivations and a prediction check. No score, prerequisite gate or local CUDA install. CPU/Mac learners can study every example in a browser. NVIDIA terms are used explicitly; Apple/AMD hardware differs.

Five short lessons

  1. 3.1 GPU execution

    Map independent outputs to threads, warps, blocks and SMs. Separate parallel work from dependencies.

    Open the visual GPU walkthrough (prototype) — explore threads, warps, blocks and SMs in a separate illustrated example.

  2. 3.2 Memory and movement

    Follow an operand through memory; distinguish capacity, traffic and coalescing.

  3. 3.3 Matrix multiplication and tiling

    Compute one output, then reuse a tile. Count work and transferred elements.

  4. 3.4 Arithmetic intensity and roofline

    Derive a resource lower bound; change compute and bandwidth independently.

  5. 3.5 Prefill, decode and evidence

    Change row count, batch and context. Turn a bottleneck prediction into a falsifiable experiment.

Memory requests and tile reuse, step by step — two optional motion walkthroughs for lessons 3.2 and 3.3.

Sources and boundaries

Original teaching examples derive from the following primary references. Invented resource limits and hardware ceilings are labeled in place. Calculated times are lower bounds, never benchmark results.

  • NVIDIA CUDA Programming Guide: SIMT kernels — execution, memory scopes and synchronization.
  • NVIDIA CUDA Best Practices Guide — coalescing, reuse and occupancy.
  • NVIDIA Matrix Multiplication Background — shapes, tiling and resource limits.
  • NVIDIA GPU Performance Background — throughput versus bandwidth.
  • Williams, Waterman and Patterson: Roofline — resource ceilings, not a latency oracle.
  • FlashAttention — attention tiling and reduced HBM traffic; deeper kernel study follows this module.

Not covered here: full CUDA implementation, profiling practice on physical hardware, tensor-core layouts, distributed inference, or a complete decoder latency model. These are next experiments, not implicit claims of this course.
