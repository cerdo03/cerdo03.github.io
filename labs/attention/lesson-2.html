Multi-Head Attention

Lesson 2.1 built one attention operation: one set of queries, keys and values, one softmax per query, one output. Real transformer layers run several of these in parallel on smaller slices of the model width and then recombine them. This lesson traces exactly how that works, tensor by tensor.

Learning goal. By the end you should be able to write the multi-head attention equations with every dimension, trace the shapes from [T, dmodel] through the head split and back, compute dhead, score-tensor sizes and projection parameter counts for any configuration, and explain what changing the head count does and does not change.

Builds on. The single-head equation from 2.1.8: Attention(Q, K, V) = softmax(QKT / √dk + M)V, with the row-vector convention (each row is one token position), the causal mask from 2.1.6 and learned projections from 2.1.2. Those steps are not repeated here.

Simplifications. One layer, one sequence (no batch dimension), biases omitted, contiguous logical tensors, every head the same size. Toy numbers are labelled as such.

2.2.1 Why multiple heads?

The limitation of one head

In single-head attention each query position produces one row of weights: a single probability distribution over the positions it may attend to. Its output is one weighted average of value vectors, all living in the same dv-dimensional space. Suppose a position would benefit from two different pieces of context, found at different positions, that matter for different reasons. One distribution must split its weight between them, and the two contributions are blended into a single averaged vector. The scores that decide the split are also computed from one comparison q·k: one notion of "relevant" per layer. What multiple heads change

Multi-head attention gives the layer H independent attention operations. Each head has its own learned projections into a smaller space of width dhead, its own scores, its own softmax and its own weighted sum. A position can therefore put most of one head's weight on one position and most of another head's weight on a different position, and the two results are kept apart until the output projection combines them. Vaswani et al. describe this as letting the model attend jointly to information from different representation subspaces at different positions, and note that a single head's averaging works against this (Attention Is All You Need, 2017, §3.2.2).

The benefit is representational flexibility: the layer can learn several different ways of comparing and mixing positions. Nothing in the equations forces it to, and nothing assigns a role to a head.

What heads do not guarantee. Heads are not designed modules. A trained head is not "the grammar head" or "the coreference head" by construction; any such description is an after-the-fact interpretation of one trained model, and attention weights alone do not explain a model's reasoning. Heads can also be redundant: for example, Michel et al. (2019) report that many heads in trained models can be removed at test time with little loss on the tasks they measured. Treat "different subspaces" as a capacity the architecture offers, not a description of what each head does.

2.2.2 Splitting dmodel into heads

Every head receives a projection of the whole input vector. The split groups projected columns, not pieces of the original embedding. Use the diagram: this view starts at the head split. Choose Previous to inspect the projection that created those columns, or Next to follow the head results.

Two widths: dmodel and dhead

dmodel
The model width: the length of the vector each token carries between layers (the residual stream). The input to attention is X ∈ ℝT×dmodel, and the layer must return the same shape so it can be added back and the next layer can consume it.
dhead
The width of one head's query, key and value vectors. In Lesson 2.1's notation each head has dk = dv = dhead. Every head here uses the same dhead for Q, K and V.
H
The number of heads.
T
The number of token positions in the sequence.

The common choice, and the one in the original Transformer, is an equal partition of the model width:

dhead = dmodel / H

With the base Transformer's dmodel = 512 and H = 8, each head works in dhead = 512 / 8 = 64 dimensions. The heads together use all 512 columns: 8 × 64 = 512. Section 2.2.6 covers architectures that choose dhead independently.

One big projection, then a reshape

Conceptually each head i has its own matrices WiQ, WiK, WiV ∈ ℝdmodel×dhead. Placing the H query matrices side by side gives one matrix:

WQ = [ W1Q | W2Q | … | WHQ ] ∈ ℝdmodel×(H·dhead)

Because matrix multiplication works column by column, Q = XWQ computes all heads' queries at once: columns 0–63 of Q are exactly XW1Q, columns 64–127 are XW2Q, and so on. The same holds for K and V. Implementations therefore run three large matrix multiplications (or one fused one) rather than 3H small ones, then split the result:

Advanced: what reshape and transpose cost in memory

In a row-major [T, 512] tensor, the 512 numbers of a row are adjacent, so viewing them as [T, 8, 64] only changes the indexing arithmetic. The transpose to [8, T, 64] is usually also a view with different strides: element (h, t, c) is still at offset t·512 + h·64 + c. Whether a kernel copies it into a head-major contiguous layout, or reads the strided view directly, is an implementation choice. Frameworks and attention kernels differ here; the logical shapes in this lesson are the same either way.

2.2.3 Attention inside each head

Each head runs exactly the scaled dot-product attention of Lesson 2.1 on its own projected slices. Use the numerical example: choose query position 3: is, then 1: The. Compare the two heads’ highlighted weight rows and outputs. At the first position the causal mask allows only that position; later positions allow different mixtures.

headi = Attention(XWiQ, XWiK, XWiV) = softmax(QiKiT / √dhead + M) Vi
Qi, Ki, Vi
Head i's queries, keys and values, each [T, dhead]: the i-th column slice of Q, K, V.
QiKiT
Head i's raw scores, [T, T]. Across all heads the score tensor is [H, T, T].
√dhead
The scale uses the head width, because each dot product sums dhead terms (the variance argument of 2.1.4). For dhead = 64 the scale is 1/8.
M
The same [T, T] causal mask for every head in a decoder.
headi
Head i's output, [T, dhead]. All heads together: [H, T, dhead].

The heads do not exchange information: head 3's softmax never sees head 5's scores. That independence is why the head axis is moved to the front. A [H, T, dhead] tensor is a batch of H separate matrix problems, which GPUs run as one batched matrix multiplication.

The compute does not grow with H

Computing one head's scores costs T · T · dhead multiply-adds (T2 dot products of length dhead). All heads: H · T2 · dhead = T2 · dmodel under equal partition, the same as one head of width dmodel. The same holds for AiVi. This is the paper's point that the total cost is similar to single-head attention at full width. What does grow with H is the number of score elements, H · T2, and so the softmax work and the memory needed if the score tensor is stored in full. The explorer in 2.2.5 shows both numbers.

2.2.4 Concatenation and the output projection WO

After attention, the H head outputs are put back side by side and multiplied by one more learned matrix. Use the diagram: this view starts at concatenation. Next shows the output projection and residual addition; Previous returns to the separate head results. Concatenation joins components without adding them; the residual addition happens afterward.

MHA(X) = Concat(head1, …, headH) WO
Concat(…)
[T, H·dhead]: row t is head1's row t, then head2's, and so on. In tensor terms: transpose [H, T, dhead] back to [T, H, dhead] and merge the last two axes.
WO
The output projection, ∈ ℝ(H·dhead)×dmodel. Under equal partition it is [dmodel, dmodel], e.g. [512, 512].
MHA(X)
[T, dmodel], the same shape as X, so it can be added to the residual stream.

Why WO is needed

Without WO, output columns 0–63 would come only from head 1, columns 64–127 only from head 2, and so on: each head would own a fixed block of the residual stream. WO lets every output dimension draw on every head. It also maps back to dmodel when H·dhead ≠ dmodel.

Advanced: concatenate-then-project equals a sum over heads

Split WO by rows into H blocks WO(i) ∈ ℝdhead×dmodel (block i is the rows that multiply head i's columns). Block matrix multiplication gives

Concat(head1, …, headH) WO = Σi=1…H headi WO(i)

So each head writes its own [T, dmodel] contribution and the layer adds them. Implementations still use the single concatenated matmul because one large multiplication is more efficient than H small ones plus a sum.

Parameter count

Without biases, the four projection matrices hold

3 · dmodel · (H·dhead) + (H·dhead) · dmodel = 4 · dmodel2  (when H·dhead = dmodel)

For dmodel = 512: 4 × 5122 = 4 × 262,144 = 1,048,576 parameters per attention layer. H does not appear: splitting the same 512 columns into 1, 8 or 64 heads only regroups them. Choosing heads under equal partition is therefore not a parameter-count decision.

    From tensor shapes to NumPy operations

    For one sequence, first project the full input: Q = X @ W_Q, with the same operation for K and V. Here T counts tokens, H counts heads, and d_head is each head’s width. The projected shape is [T, H * d_head].

    1. Split projected columns: Q.reshape(T, H, d_head).transpose(1, 0, 2) gives [H, T, d_head]. Apply the same reshape and transpose to K and V. Reshape groups columns; transpose changes the order of axes.
    2. Reuse single-head attention: select one head’s [T, d_head] Q, K and V matrices. Run the same scaled scores, causal mask, row-wise softmax and weighted-value sum as Lesson 2.1. Each head returns [T, d_head]; stacking the results gives [H, T, d_head]. Heads do not share a softmax.
    3. Join, then project: if heads holds those results, heads.transpose(1, 0, 2).reshape(T, H * d_head) restores token-first order and joins head components. Multiplying that matrix by W_O returns [T, d_model]. Reshaping directly without the transpose would mix token and head ordering.

    This is an axis-order reference, not a complete implementation. It assumes equal query/key/value head widths and aligned self-attention positions; it does not introduce GQA or a KV cache.

    With the defaults (T = 1024, H = 8), the score tensor holds 8 × 1024 × 1024 = 8,388,608 elements. At H = 64 it holds 67,108,864, eight times more, while the QKT multiply-adds stay at 10242 × 512 = 536,870,912. The head count trades fewer, wider comparisons for more, narrower ones; it does not change the matmul budget.

    2.2.6 Head count, head dimension and what heads do not tell us

    More heads is not automatically better

    With a fixed model width and equally sized heads, more heads means fewer components per head. Each head has less space for its comparisons, while the layer calculates more separate attention patterns. More heads therefore does not automatically improve quality.

    • Lower-dimensional comparisons. Head i's score matrix QiKiT is a product of a [T, dhead] and a [dhead, T] matrix, so its rank is at most dhead. At H = 64 with dmodel = 512, each head compares positions using only 8 numbers per vector.
    • More score matrices. H·T2 score elements and H softmaxes per query position. Very small heads also tend to use GPU matrix units less efficiently; attention kernels are commonly tuned for head widths such as 64 or 128.

    Fewer, wider heads have the opposite trade-off: fewer independent attention patterns per layer. The original paper's ablation (Table 3, English–German translation development set) varied the head count while keeping compute constant: single-head attention was clearly worse than the best setting, and quality also dropped with too many heads. Head count is a tuned hyperparameter, and results from one model and task do not transfer as a rule. More heads does not mean better quality.

    dhead does not have to equal dmodel / H

    Equal partition is a convention, not a requirement. Some architectures set dhead directly, so H·dhead can be larger or smaller than dmodel (model configuration files often expose a separate head-dimension field for this). The equations are unchanged; only the widths move:

    • WQ, WK, WV ∈ ℝdmodel×(H·dhead) and the concatenation is [T, H·dhead].
    • WO ∈ ℝ(H·dhead)×dmodel maps back to the model width, so the output is still [T, dmodel].
    • Parameters become 4 · dmodel · H · dhead and the score multiply-adds T2 · H · dhead; now they do depend on the choice.

    Switch the explorer to Independent to see WO change shape. For example, dmodel = 512, H = 8, dhead = 128 gives WQ = [512, 1024], a [T, 1024] concatenation and WO = [1024, 512], with 4 × 512 × 1024 = 2,097,152 projection parameters.

    Engineering implication: heads shape the KV cache

    During decoding the model stores each processed position's keys and values for every head. In the multi-head attention described here, every head has its own K and V, so each token adds 2 · H · dhead numbers per layer, which is 2 · dmodel under equal partition. Lesson 2.3 shows how multi-query and grouped-query attention keep all the query heads while sharing fewer K/V heads, and Lessons 2.4–2.5 turn this into bytes.
