Optional · What changes in the KV cache?

One sequence, two layers, BF16 / FP16 storage (2 bytes per element). Same query count and head width for every comparison; GQA reference uses one KV head per four queries (two per group when there are only four queries). Changing layout describes a different model architecture, not a lossless runtime switch for an existing checkpoint.

Raw K/V payload only. Excludes weights, activations, allocator waste, cache metadata and temporary repetitions of shared K/V. Fewer KV bytes do not guarantee a proportional speedup or equal model quality. This view counts storage for all selected positions, even when inspecting an earlier position.

Architecture summary, notation and sources

Token embeddings + learned position embeddings → decoder block 1 → decoder block 2 → final LayerNorm → vocabulary projection → logits. In each pre-norm block: LayerNorm → causal attention → add incoming vector → LayerNorm → FFN → add the vector after attention. The FFN uses Linear → GELU → Linear with 4× hidden width. Other decoder families can use rotary positions, RMSNorm and gated FFNs. There is no encoder or cross-attention here.

Attention: O = softmax(QKᵀ / √D + M)V. Each future position receives mask −∞, so its weight is exactly zero. Softmax is applied over key positions for each query row. Selected query position can attend itself. Causal visibility does not mean every allowed position gets equal weight.
