    Change the assumption

    When can a write finish?

    Three home replicas: A, B and C. Acknowledgements follow durable storage immediately in this toy schedule. Times are invented, in milliseconds (ms).

    Fixed deadline: 6 ms. A: 1 ms, B: 3 ms, C: 8 ms; fallback D: 4 ms. An unreachable home gets no new copy in this scenario. Fallback replaces that home only. No fallback is selected merely because C is slow.

    See persistence, replies and deadline

      Same histories / different meaning

      What should be in the cart?

      Common base: book. One known edit adds pen; another removes book. Two snapshots alone may not reveal these intentions. We supply them explicitly for the second policy.

      Branch D3 · add pen

      book + pen

      Branch D4 · remove book

      empty cart

      Both options record the combined history. Vector clocks cannot choose between these application policies. The edit-aware option assumes the application knows the common base and both intentions.

      Keep the distinctions

      A small guide to the moving parts

      Replica
      A stored copy on a distinct physical host. Copies and versions are different things.
      Coordinator
      The node organizing this request and collecting replies. Not a permanent elected leader.
      Context
      Metadata passed back with a write so its earlier histories are included.
      Concurrent siblings
      Versions where neither history contains the other. Storage preserves both for application reconciliation.
      Vector clock
      Coordinating-node counters describing causal history. Counters are not seconds.
      , and
      N: desired distinct replicas. R: read participation threshold. W: write participation threshold.
      Hinted handoff
      A temporary fallback returns a copy to its intended home after recovery.
      Read repair
      A read discovers stale ancestors and can update their replicas.
      Anti-entropy
      Background synchronization of shared ranges, using Merkle trees to locate differences.

      What this model leaves out

      The diagrams isolate teaching moments; their geometry is not network wiring. Synthetic timings are not performance measurements. Fixed participant overlap does not establish linearizability; sloppy placement can change those participants. No production availability estimate, unlimited-failure guarantee or current DynamoDB behavior is implied.
