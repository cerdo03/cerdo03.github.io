Why tiling needs online normalization

A tile is a small matrix patch. It lets us compute and consume temporary scores while they are in the active working set, then reuse their storage.

What you will be able to explain

Trace tile residency; account for transfers; explain larger-tile resource trade-offs without promising speedup.

In lesson 3.3, operand reuse reduced logical loads for matrix multiplication. Attention adds normalization across all allowed keys: online summaries from lesson 4.2 let us finish a row without keeping every score in global memory.

Count the chosen loop, then discuss its limits

More query rows per tile can reuse each K/V load across more queries. Larger tiles also require more active state.

For query-tile outer loop, key/value-tile inner loop: Q reads Tq × dk elements; K/V reads ceil(Tq / Br) × Tk × (dk + dv); O writes Tq × dv. This noncausal count assumes query and summary remain resident. Br means query rows per tile; Bc means key rows per tile.

Explore in the tile walkthrough computes a separate 8 × 8 sizing example. All totals come from the same event ledger as its read/write counts. Peak modeled storage includes Q/K/V tiles, float32 score scratch, numerator and row statistics. No occupancy percentage or speedup is inferred.

for query_tile in Q:
    load(query_tile)
    summary = empty_rows()
    for key_tile, value_tile in KV:
        load(key_tile, value_tile)
        scores = scaled_masked_dot(query_tile, key_tile)
        summary = merge(summary, scores, value_tile)
    store(normalize(summary))
Causal tiles, versions and backward pass

Skip tiles wholly above the causal diagonal. A diagonal tile can contain masked cells; loaded slots and valid score pairs are separate counts. Ragged last tiles use valid dimensions in this analytical model. Real kernels may pad loads.

This query-outer schedule is a teaching choice, not a transcription of FlashAttention Algorithm 1. FlashAttention-2 changes work partitioning and reduces non-matmul overhead. Larger FlashAttention versions bring further hardware-specific techniques; learning the invariant does not require replaying each version.

Training backward can recompute score/probability tiles from saved inputs and normalization statistics, trading extra computation for less stored activation traffic. This module’s main path is inference forward; no backward kernel implemented here.
