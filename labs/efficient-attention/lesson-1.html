Where attention spends memory

Separate persistent KV, temporary workspace and transferred bytes before choosing an optimization.

What stays, what is temporary?

A stored key/value row survives into later decode steps. A score or probability buffer can be temporary workspace for one attention call.

One query is not a new square matrix

Let Tq be query rows processed now and Tk be visible key positions. Scores have shape Tq × Tk, not always Tk × Tk.

Q [Tq × dk] · Kᵀ [dk × Tk] → scores [Tq × Tk].
A [Tq × Tk] · V [Tk × dv] → O [Tq × dv].

Tq/Tk count rows; dk is query/key width; dv is value/output width. Ordinary decode usually adds one query per active sequence. Prefill can process many supplied queries under causal visibility. Self-attention can include the newly processed position.

For 4,096 queries and keys, one two-byte dense score buffer is 32 MiB. A separate probability buffer adds 32 MiB.

Full dense allocation may include masked entries. Causal allowed-pair count does not by itself imply triangular physical storage.

Footprint and traffic answer different questions

Footprint asks what is live together. Traffic asks how many bytes cross a named boundary over the whole operation.

  1. Compute scores and write them to global memory.
  2. Read scores, compute normalization, write probabilities.
  3. Read probabilities and values; write final attention output.

For equal two-byte score/probability arrays: two distinct buffers occupy 4 × Tq × Tk bytes together in this explicitly materialized baseline. Writing and reading each once transfers 8 × Tq × Tk bytes. Q/K/V input reads and output stores are additional. A different allocation schedule can have a different peak.

Do not add a cache’s capacity to a transfer counter. Do not call logical loads measured DRAM bytes: hardware caches, spills and padding can change actual traffic.

scores = Q @ K.T / sqrt(dk)   # global score write
weights = softmax(scores + mask)  # score read + probability write
output = weights @ V          # probability read + output write

Source: FlashAttention §2.2, materialized baseline
