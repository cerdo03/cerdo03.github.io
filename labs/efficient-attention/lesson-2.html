Softmax without keeping every score

Preserve exact attention mathematically by combining stable summaries across tiles.

Why subtract the maximum?

Softmax turns scores into weights. Exponentials can overflow, so subtract the row maximum before exponentiating; normalization cancels the common scale.

weight at position j = exp(scoreⱼ − maximum) / Σ exp(score − maximum).

All weights use the same denominator over every allowed key. Masked keys contribute exactly zero; small positive unmasked weights are not mask zeros.

Numerical fixture: four positions, Q = [1, 0], Kⱼ = [√2 × scoreⱼ, 0], scores = [1, 2, 3, 4], V = [[1, 0], [0, 1], [1, 1], [2, 0]]. Thus Q·Kⱼ / √2 produces the stated score. These invented Q/K/V are not changed embeddings from Module 2.

Carry a summary, not all previous scores

Keep the largest score so far, the denominator at that scale, and an unnormalized weighted-value sum. New tiles update this summary.

m
Running maximum among allowed scores seen so far.
ℓ
Sum of exp(score − m), not a probability.
u
Vector Σ exp(score − m) × V.
α
exp(old m − new m); corrects earlier contributions to the new scale.

Start m = −∞, ℓ = 0, u = [0, 0]. When a larger maximum arrives, rescale both ℓ and every component of u before adding the new tile. Only after all keys: output = u / ℓ.

First tile: m = 2, ℓ ≈ 1.36788, u ≈ [0.36788, 1]. Second tile raises the maximum to 4; multiply earlier contributions by exp(−2).

Read each update in the code

The numerator is deliberately unnormalized. Adding independent tile averages loses their different denominators.

m′ = max(m, max(tile scores))
α = exp(m − m′)
pⱼ = exp(scoreⱼ − m′)
ℓ′ = αℓ + Σpⱼ
u′ = αu + ΣpⱼVⱼ
o = u / ℓ after the final tile
for tile in key_value_tiles:
    new_m = max(m, max(tile.scores))
    alpha = exp(m - new_m) if denominator > 0 else 0
    p = exp(tile.scores - new_m)
    denominator = alpha * denominator + sum(p)
    numerator = alpha * numerator + p @ tile.values
    m = new_m
output = numerator / denominator

Example trap: two equal-size tiles can still have different softmax mass. Averaging their independently normalized outputs is generally wrong. Merge unnormalized summaries instead.

Numerical and masking boundaries

An entirely masked tile leaves the existing summary unchanged. This model explicitly handles an empty summary rather than evaluating −∞ − (−∞). A completely masked row returns zero by declared teaching convention. Production APIs may define this differently. Large finite scores remain stable; rounding and accumulation order can produce tiny output differences.

Causal chunk with prefix length p: query row i may read keys j ≤ p + i, using absolute zero-based positions. A single decode query over a cache is rectangular; a top-left square mask can wrongly hide earlier keys.
